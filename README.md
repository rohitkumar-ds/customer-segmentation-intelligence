# Customer Segmentation Intelligence

An end-to-end customer segmentation system that converts transaction-level data into behavioral customer segments, business personas, and customer similarity lookups.

---

# 1. Why This Project

Traditional RFM segmentation captures **Recency, Frequency, and Monetary value**, but misses behavioral differences such as product/category exploration, purchase quantity, AOV, and purchase intervals.

This project extends RFM with:

- Average Order Value
- Total Quantity Purchased
- Unique Products
- Unique Categories
- Average Days Between Purchases

The objective is to understand **how customers behave**, not only how much they spend.

---

# 2. Architecture & Code Flow

The training pipeline is controlled by `train_pipeline.py`. Each module performs one stage and passes its output to the next stage.

```text
Raw Transactions
      ↓
train_pipeline.py
      ↓
data_processing.py
      ↓
feature_engineering.py
      ↓
data_processing.py
      ↓
clustering.py
      ↓
model_evaluation.py
      ↓
utils.py
      ↓
Saved Models / CSV / JSON
      ↓
app.py
      ↓
Streamlit Dashboard
```

### Code Flow

| Step | File | Responsibility |
|---:|---|---|
| 1 | `train_pipeline.py` | Orchestrates the complete training workflow |
| 2 | `src/data_processing.py` | Loads, validates, cleans and preprocesses transactions |
| 3 | `src/feature_engineering.py` | Creates RFM and behavioral customer features |
| 4 | `src/data_processing.py` | Applies imputation, IQR capping and `log1p` transformation |
| 5 | `src/clustering.py` | Scales features, selects K, trains K-Means and performs PCA |
| 6 | `src/model_evaluation.py` | Compares K-Means, Agglomerative and DBSCAN |
| 7 | `src/utils.py` | Creates business labels and saves artifacts |
| 8 | `app.py` | Loads saved artifacts and presents the Streamlit dashboard |

The dashboard does **not retrain the model**. It consumes the artifacts generated by `train_pipeline.py`.

# 3. Data & Feature Engineering

`data/raw_transactions.csv` contains transaction-level information such as:

- `TransactionID`
- `CustomerID`
- `TransactionDate`
- `ProductID`
- `Category`
- `Quantity`
- `UnitPrice`

The cleaning stage removes duplicates and invalid records and calculates:

```text
TotalAmount = Quantity × UnitPrice
```

Customer-level features are then created:

| Feature | Meaning |
|---|---|
| Recency | Days since last purchase |
| Frequency | Number of unique transactions |
| MonetaryValue | Total customer spend |
| AOV | Average spend per transaction |
| TotalQuantityPurchased | Total units purchased |
| UniqueProducts | Number of distinct products |
| UniqueCategories | Number of distinct categories |
| AverageDaysBetweenPurchases | Mean gap between purchases |

---

# 4. Preprocessing

The model does not cluster raw customer values directly.

```text
Customer Features
      ↓
IQR Outlier Capping
      ↓
log1p Transformation
      ↓
StandardScaler
      ↓
Clustering
```

High-value customers can heavily distort Euclidean distance. IQR capping limits extreme values without deleting customers, while `log1p` reduces long-tailed distributions.

---

# 5. Clustering Strategy

`src/clustering.py` evaluates candidate K values using:

- K-Means inertia
- Silhouette Score

`choose_best_k()` selects the K with the highest valid Silhouette Score.

For the supplied dataset:

```text
Best K = 2
Silhouette Score = 0.4168
```

PCA is fitted afterward for 2D/3D visualization. It is not used as the primary clustering space.

---

# 6. Model Comparison

`src/model_evaluation.py` compares three algorithms:

| Model | Silhouette ↑ | Davies-Bouldin ↓ | Clusters | Noise % |
|---|---:|---:|---:|---:|
| K-Means | 0.4168 | 0.9705 | 2 | 0.0% |
| Agglomerative | **0.4233** | **0.9342** | 2 | 0.0% |
| DBSCAN | 0.3220 | 0.9718 | 13 | 51.3% |

DBSCAN labels noise as `-1`. `_safe_clustering_metrics()` handles these observations separately and reports `NoisePercentage`.

Although Agglomerative has slightly better internal metrics, K-Means is retained because it is simpler to operationalize, serialize and use for customer assignment.

# 7. Business Segmentation

`src/utils.py` translates cluster behavior into business-readable segments.

| Segment | Typical Strategy |
|---|---|
| High-Value Loyal Customers | Loyalty rewards and personalized offers |
| At-Risk Customers | Win-back campaigns |
| Low-Engagement Customers | Reactivation and product discovery |
| High-Spend Occasional Customers | Cross-selling and frequency building |
| Regular Customers | Continued engagement |

The ML cluster identifies behavioral similarity; the business layer interprets that behavior.

---

# 8. Customer Similarity

`find_similar_customers()` uses standardized customer vectors and Euclidean distance.

```text
Customer
   ↓
Standardized Feature Vector
   ↓
Distance to Other Customers
   ↓
Nearest Customers
   ↓
Lookalike / Retention / Cross-Sell Targeting
```

This is a behavioral similarity engine, not a full recommendation or conversion-probability model.

# 11. Engineering Challenges

### 11.1 Extreme Spend Skew

High-value customers distorted K-Means distance.

**Solution:** IQR capping → `log1p` transformation → StandardScaler.

### 11.2 DBSCAN Noise

DBSCAN's `-1` labels caused standard clustering metrics to fail.

**Solution:** `_safe_clustering_metrics()` excludes noise from metric calculations and reports noise percentage separately.

### 11.3 Cold Start

A missing or empty CSV could stop the training pipeline.

**Solution:** `generate_dummy_transactions()` creates reproducible synthetic data as a development fallback.
